# 生成与优化知识大纲

先读取仓库根目录的 [AGENTS.md](../../../AGENTS.md)，遵守其中的写入、确认和来源约定。

## 工作流程

1. 从用户指定主题的总纲出发，沿链接按需读取相关子纲与笔记；未限定范围时先检查 Maps 及 Notes 文件清单。没有主题大纲时说明现状，根据用户指定的范围和可用资料提出最小结构；空仓库不凭空设计领域体系。
2. 检查重复或近义条目、层级混杂、职责重叠、断链、未被大纲索引的笔记，以及标题和笔记内容不符的问题。目录 README 不作为孤立知识笔记。
3. 生成或调整大纲时，先检索已有知识归属，再判断单页是否足够。范围不同、可独立检索或被多个主题复用的分支可拆成子纲；总纲保留范围、入口与跨主题依赖，子纲展开本域知识。使用目录时，以目录内的 `README.md` 为唯一索引，把本主题的子纲集中在目录内，上级索引链接至子目录的 `README.md`。通用基础优先复用已有链接，暂无内容先用纯文本记录。区分已验证的结构问题与建议补充的知识；没有用户反馈时保持“未评估”。
4. 提供最小变更方案，列出各文件的范围、受影响条目、上级入口、跨主题链接及调整理由。拆分、移动或重命名时查找入链，并将链接修复纳入同一方案；笔记合并、重要覆盖或删除单独说明影响。
5. 生成、检查或优化请求本身不代表已确认具体修改。先返回可审阅方案，收到确认后只执行获确认部分；用户已确认同一具体方案时直接执行，无须重复询问。
6. 执行后验证各级目录索引、相对链接和差异。移动总纲或子纲时，更新其他文档及结构化清单中引用的路径；保留原有来源及用户给定的掌握状态。不要为补齐大纲创建空笔记或自动填充未经要求的知识。

## 交付

检查阶段返回问题、证据及待确认方案，无问题则说明检查范围与结果。执行阶段报告实际变更、链接修复和仍需用户判断的事项；未确认部分继续保持原状。
