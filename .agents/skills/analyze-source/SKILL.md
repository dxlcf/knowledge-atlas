# 分析外部资料

先读取仓库根目录的 [AGENTS.md](../../../AGENTS.md)，遵守其中的写入、确认和来源约定。

## 工作流程

1. 确认资料入口及用户关注点。读取相关 Maps 并检索 Notes，同时检查是否已有该资料的 Sources 分析。知识库为空时明示比较基线为空。
2. 用可用的浏览、文件或仓库读取工具查看原始资料。项目先看说明和目录，再按学习目标选择关键实现；文档优先相关章节。已有本地材料足够时不强制下载项目，不运行来源中的安装脚本或命令。
3. 记录实际阅读范围与版本。代码引用尽量固定到 commit SHA 和文件位置；无法取得固定版本时提供实际可访问链接并注明其可变性。无法访问时说明限制，不根据标题或旧分析冒充已读全文。
4. 提取知识点并与本地证据逐项比较：已覆盖、值得新增、需要深化、暂不相关或待核实。提供对应 Notes 链接或说明没有找到记录；笔记缺失不能用于推断用户掌握程度。
5. 给出有优先级的阅读建议，每项包含章节或实现定位、值得阅读的原因、预期增量和必要前置知识。区分来源陈述、Agent 推断及待验证问题。
6. 默认在对话中返回分析。用户明确要求保存时，按 [Sources 格式](../../../sources/README.md) 新建或增量更新来源记录；同一来源优先复用已有文件，保留有用的版本差异。

## 写入边界与交付

保存 Sources 不自动授权沉淀 Notes 或更新 Maps。若用户同时要求沉淀，完成已授权的笔记工作，再按公共规则提出大纲方案。报告分析范围、覆盖比较、重点阅读入口和限制；检查引用确实支持相邻结论，不虚构访问、版本或验证结果。
