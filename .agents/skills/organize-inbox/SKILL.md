# 整理 Inbox

先读取仓库根目录的 [AGENTS.md](../../../AGENTS.md)，遵守其中的写入、确认和来源约定。

## 工作流程

1. 确定指定文件或时间范围。对“最近”优先使用文件名中的日期和内容日期，并在结果中说明范围；日期冲突或不足以判断时请求澄清，不把 Git 检出产生的修改时间当作记录时间。排除目录 README 和已完整处理且未变化的内容。
2. 提取独立知识点，区分可沉淀结论、重复内容、个人想法和待解决问题。保留不确定性，不把随手猜测改写为确定事实。
3. 读取相关 Maps，按标题、关键词、别名检索 Notes，必要时检查关联 Sources。逐项决定补充已有笔记、新建笔记或不写入。
4. 在授权范围内写入精炼笔记，保留原有有效内容和来源；需要覆盖冲突结论的部分先给出具体建议。格式参考 [Notes 说明](../../../notes/README.md)。
5. 汇总拟新增的大纲及索引链接，展示具体位置和内容，待用户确认后写入 Maps。没有合适主题时建议最小结构，不自行创建领域分类。
6. 仅对已实际沉淀的部分在 Inbox 追加处理记录：实际日期、已处理范围、目标相对链接及剩余问题。大纲待确认时注明，不标记整个流程已完成；不删除原文，不重复追加无变化的记录。

## 交付

报告处理范围、知识点到目标笔记的映射、跳过的重复项、未解决问题，以及待确认的大纲或覆盖方案。没有有价值增量时说明原因，不创建空笔记。检查所有新链接与修改差异。
